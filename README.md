# ربات فروشگاهی VPN — Cloudflare Workers

یک ربات تلگرام فروش و مدیریت اشتراک VPN که برای اجرا روی Cloudflare Workers
ساخته شده (کاملاً webhook-based، بدون polling). ذخیره‌سازی هم طبق درخواستت
روی Cloudflare KV هست.

## چی کامل ساخته شده

**بخش کاربر:** `/start` + بررسی عضویت اجباری، لینک دعوت (رفرال)، منوی اصلی،
اکانت تست، مسیر خرید (دسته‌بندی ← محصول ← کد تخفیف ← پرداخت از کیف پول) با
ساخت خودکار اکانت روی پنل، کیف پول (شارژ کارت‌به‌کارت با رسید + تأیید ادمین)،
«سرویس‌های من» با بروزرسانی مصرف، پشتیبانی (FAQ + تیکت با پاسخ ادمین).

**پنل‌های پشتیبانی‌شده:** Marzban، 3x-ui/Sanaei، و Pasargad (PasarGuard —
فورک مرزبان). اضافه‌کردن هرکدوم از پنل ادمین دقیقاً یک فرم مشترکه: آدرس پنل،
یوزرنیم ادمین، رمز عبور ادمین.

**پنل مدیریت (`/admin`):** کاربران (جستجو/مسدودسازی/افزایش-کاهش موجودی/ریست
تست)، محصولات، دسته‌بندی‌ها، پنل‌ها (افزودن/فعال‌سازی/تست اتصال)، پروفایل‌ها،
کدهای تخفیف، تأیید پرداخت‌ها، Broadcast (همه/دارای‌سرویس/بی‌سرویس)، مدیریت
نقش ادمین‌ها (Owner/Manager/Support)، کانال‌های اجباری، تنظیمات + متن‌های
قابل‌ویرایش، آمار، Audit Log، پاسخ به تیکت‌ها.

## چیزهایی که کامل نیست یا نیاز به تصمیم تو داره

طبق چک‌کردنی که با هم انجام دادیم، این موارد از پرامپت اصلی هنوز جا مونده:

1. **درگاه پرداخت آنلاین** — فعلاً فقط یک پیام «هنوز وصل نشده» نشون میده و
   کاربر رو به کارت‌به‌کارت ارجاع می‌ده. هروقت یک درگاه انتخاب کردی (زرین‌پال،
   آیدی‌پی، نکست‌پی و…) بگو تا آداپتور و مسیر callback‌ش رو اضافه کنم.
2. **inbound پنل‌ها** — وقتی یک پروفایل (VLESS Reality، VMess WS و…) از پنل
   ادمین اضافه می‌کنی، فیلد `inbound_tag` (مرزبان/پاسارگاد) یا `inbound_id`
   (3x-ui) خالی می‌مونه، چون به تنظیمات واقعی اینباند خود پنل تو بستگی داره.
   باید مستقیم توی کلید KV مربوط به همون پروفایل (`profile:*`) پرش کنی، یا
   بگو تا این مرحله رو هم به ویزارد اضافه کنم.
3. **QR Code** — ساخته نشده؛ سرویس‌ها/اکانت تست فعلاً فقط لینک Subscription و
   (در صورت برگشت از پنل) متن Config رو نشون می‌دن.
4. **ویرایش محصول/پنل/دسته‌بندی/تخفیف/کانال** — فقط افزودن، فعال/غیرفعال‌سازی
   و حذف ساخته شده؛ برای تغییر یک آیتم موجود باید حذف و دوباره اضافه‌ش کنی.
5. **تأییدیه «آیا مطمئن هستید؟»** — برای عملیات حساس (حذف محصول/پنل/کانال،
   مسدودکردن کاربر، حذف ادمین) هنوز ساخته نشده؛ این‌ها الان بلافاصله انجام
   می‌شن.
6. **Broadcast در مقیاس بزرگ** — `admin:broadcast` توی یک حلقه‌ی تکی پیام‌ها
   رو می‌فرسته؛ برای چند صد کاربر مشکلی نیست، ولی برای تعداد خیلی زیاد بهتره
   با Cloudflare Queues دسته‌بندی بشه.

جزئیات کامل‌تر (کدوم بخش‌های پنل ادمین دقیقاً چی کم دارن) رو توی همون پیام قبلی
چت باهم مرور کردیم — اگه خواستی از اونجا هم می‌تونی چک‌لیست کامل رو ببینی.

## نصب و راه‌اندازی

```bash
cd vpn-bot
npm install

# ۱. ساخت دو KV namespace
npx wrangler kv namespace create BOT_KV
npx wrangler kv namespace create BOT_SESSIONS
# آیدی‌هایی که برمی‌گردن رو توی wrangler.toml بخش kv_namespaces جای‌گذاری کن

# ۲. تنظیم secret ها
npx wrangler secret put BOT_TOKEN        # از @BotFather بگیر
npx wrangler secret put WEBHOOK_SECRET   # یک رشته‌ی رندوم دلخواه
npx wrangler secret put OWNER_ID         # آیدی عددی تلگرام خودت

# ۳. دیپلوی
npx wrangler deploy
```

## بعد از دیپلوی

**ثبت webhook** (مقادیر رو جایگزین کن):
```
https://api.telegram.org/bot<BOT_TOKEN>/setWebhook?url=https://<your-worker>.workers.dev&secret_token=<WEBHOOK_SECRET>
```

**اضافه کردن خودت به‌عنوان اولین Owner.** ربات این کارو خودکار انجام نمی‌ده،
باید یک‌بار مستقیم توی KV بنویسی:
```bash
npx wrangler kv key put --binding=BOT_KV "config:admins" '[{"id":123456789,"role":"owner"}]'
```
(به‌جای `123456789` همون آیدی عددی تلگرامی که برای `OWNER_ID` گذاشتی رو بذار)

**بعدش از داخل خود ربات (`/admin`):**
- 🖥 پنل‌ها ← پنل Marzban / 3x-ui / Pasargad خودت رو اضافه کن
- 👤 پروفایل‌ها ← برای هر پنل حداقل یک پروفایل بساز (بعد `inbound_tag` یا
  `inbound_id` رو طبق نکته‌ی بالا توی KV تنظیم کن)
- 📂 دسته‌بندی‌ها ← 🛍 محصولات ← هر محصول رو به یک پنل + پروفایل وصل کن
- 📢 کانال‌ها ← کانال‌های عضویت اجباری رو اضافه کن (ربات باید ادمین همون
  کانال باشه تا بتونه عضویت رو چک کنه)
- ⚙️ تنظیمات ← شماره کارت/نام صاحب کارت، محدودیت تست، درصد پاداش دعوت، آیدی
  پشتیبانی

## اختیاری: سیستم انقضای خودکار

`src/index.js` یک تابع `scheduled()` داره که سرویس‌های منقضی‌شده رو غیرفعال
می‌کنه و ۲۴ ساعت قبل هشدار می‌ده. این تابع تا وقتی یک Cron Trigger اضافه
نکنی غیرفعاله — این خط رو به `wrangler.toml` اضافه کن:

```toml
[triggers]
crons = ["0 * * * *"]   # هر ساعت یک‌بار
```

## یک نکته درباره‌ی خود KV

Cloudflare KV سازگاری نهایی (eventually consistent) داره و تراکنش (transaction)
نداره. برای یک ربات فروشگاهی در ترافیک معمولی مشکلی پیش نمیاد (تغییر موجودی
کیف پول به‌صورت خواندن-و-نوشتن برای هر کاربر انجام می‌شه)، ولی اگه یک روز
انتظار نوشتن هم‌زمانِ زیاد روی کیف پول *یک* کاربر خاص رو داشتی (مثلاً تپ‌های
پشت‌سرهم)، بهتره موجودی کیف پول رو بعداً به Durable Objects یا D1 منتقل کنی.
بقیه‌ی بخش‌ها چون همه از `src/lib/kv.js` عبور می‌کنن، این تغییر رو بدون
دردسر زیاد قبول می‌کنن.
