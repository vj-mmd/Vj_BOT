# 🤖 Vj_BOT — ربات فروشگاهی VPN روی Cloudflare Workers

ربات تلگرام فروش و مدیریت اشتراک VPN، کاملاً **webhook-based** (بدون پولینگ)،
اجرا روی **Cloudflare Workers** و ذخیره‌سازی روی **Cloudflare KV**. هیچ سروری
لازم نیست — همه‌چیز روی زیرساخت رایگان/ارزان کلادفلر بالا میاد.

این راهنما از صفر تا صد رو پوشش می‌ده: از گرفتن کد از گیت‌هاب تا آنلاین شدن
ربات و شناخت کامل پنل مدیریت.

## ✨ امکانات ربات

### 👤 بخش کاربر
- `/start` با پشتیبانی از لینک رفرال (`?start=ref<id>`)
- عضویت اجباری در چند کانال قبل از استفاده از ربات
- پذیرش قوانین + احراز هویت با شماره تلفن تلگرام (دکمه Share Contact)
- 🦠 **اکانت تست رایگان** — یک‌بار به ازای هر کاربر، فقط لینک Subscription (بدون کانفیگ خام)
- 💥 **خرید اشتراک** — دسته‌بندی ← محصول ← کد تخفیف (اختیاری) ← پرداخت از کیف پول ← ساخت خودکار اکانت روی پنل
- 💸 **کیف پول** — شارژ کارت‌به‌کارت با ارسال رسید و تأیید دستی ادمین، مبالغ پیشنهادی + مبلغ دلخواه، تاریخچه تراکنش‌ها
- 🔍 **سرویس‌های من** — مشاهده حجم/انقضا، بروزرسانی مصرف از پنل، ♻️ تمدید خودکار (ریست زمان و حجم) با کسر از کیف پول
- 🗣 **دعوت دوستان** — پاداش درصدی خودکار روی اولین خرید موفق کاربر دعوت‌شده
- ☎️ **پشتیبانی** — سوالات متداول (FAQ) + تیکت آنلاین با پاسخ مستقیم ادمین از داخل ربات

### 🛠 پنل مدیریت (`/admin`)
- 👥 مدیریت کاربران (جستجو، مسدود/رفع مسدودی، افزایش/کاهش موجودی، ریست سهمیه تست، سرویس‌ها و سفارش‌های هر کاربر)
- 🛍 مدیریت محصولات و 📂 دسته‌بندی‌ها
- 🖥 مدیریت پنل‌های VPN (افزودن، فعال/غیرفعال، تست اتصال) — Marzban / 3x-ui / PasarGuard
- 👤 مدیریت پروفایل‌ها (پروتکل‌ها) روی هر پنل
- 🎟 کدهای تخفیف (درصدی یا مبلغ ثابت، سقف استفاده، محدود به محصول/دسته)
- 💳 تأیید/رد رسیدهای پرداخت + 💰 مدیریت مستقیم کیف پول کاربران
- 📢 پیام همگانی (Broadcast) به همه / فقط دارای‌سرویس / بدون سرویس
- 📡 مدیریت کانال‌های عضویت اجباری
- 👨‍💼 مدیریت ادمین‌ها (نقش Owner / Manager / Support)
- 📊 آمار کلی + 📝 گزارش فعالیت ادمین‌ها (Audit Log)
- 🎫 تیکت‌های پشتیبانی

### ⚙️ تنظیمات (کاملاً از داخل ربات، بدون نیاز به ویرایش کد)
- 🔌 **روشن/خاموش کردن کل ربات** با یک دکمه — وقتی خاموشه فقط ادمین‌ها دسترسی دارن
- 📝 **متن‌های ربات** — تقریباً هر پیامی که کاربر می‌بینه (~۴۵ متن، دسته‌بندی‌شده) قابل ویرایشه
- 🎨 **رنگ دکمه‌ها** — رنگ تک‌تک دکمه‌های ربات (کاربر + ادمین) قابل تنظیمه (پیش‌فرض/آبی/سبز/قرمز)
- ❓ **سوالات متداول** — افزودن/ویرایش/حذف کامل از پنل
- 💳 شماره کارت، حداقل شارژ، درصد پاداش رفرال، تنظیمات اکانت تست
- 📊 **گروه لاگ** (Forum-based، هر رویداد تو تاپیک خودش: کاربر جدید، خرید، شارژ، تمدید، تست، پشتیبانی)
- 📢 **کانال گزارش عمومی** — هر خرید/شارژ موفق با نام و آیدی کاربر پابلیش می‌شه

## 📥 مرحله ۱ — گرفتن کد از گیت‌هاب

اگه کد رو به‌صورت zip دارید:

1. یک ریپازیتوری جدید و **خالی** تو گیت‌هاب بسازید (بدون README/gitignore پیش‌فرض)
2. zip رو اکسترکت کنید و داخل پوشه پروژه:

```bash
git init
git add .
git commit -m "Initial commit"
git branch -M main
git remote add origin https://github.com/<your-username>/<repo-name>.git
git push -u origin main
```

اگه قبلاً یه ریپو گیت‌هاب دارید، فقط clone کنید:

```bash
git clone https://github.com/<your-username>/<repo-name>.git
cd <repo-name>
```

## 🗄 مرحله ۴ — ساخت KV Namespace ها

ربات از دو KV namespace استفاده می‌کنه: یکی برای داده‌های اصلی (`BOT_KV`) و
یکی برای سشن‌های موقت (`BOT_SESSIONS`).

```bash
npx wrangler kv namespace create BOT_KV
npx wrangler kv namespace create BOT_SESSIONS
```

هر دستور یه چیزی شبیه این چاپ می‌کنه:

```
{ binding = "BOT_KV", id = "abcd1234..." }
```

**آیدی‌هایی که گرفتید رو کپی کنید** و داخل فایل `wrangler.toml` جایگزین
مقادیر فعلی `id` کنید:

```toml
kv_namespaces = [
  { binding = "BOT_KV", id = "<آیدی BOT_KV شما>" },
  { binding = "BOT_SESSIONS", id = "<آیدی BOT_SESSIONS شما>" }
]
```

> ⚠️ آیدی‌هایی که الان تو `wrangler.toml` هست مال یه نمونهٔ دیگه‌ست — حتماً
> با آیدی‌های خودتون جایگزین کنید، وگرنه دیتای ربات شما با اون namespace
> قاطی می‌شه یا دیپلوی fail می‌کنه.

می‌تونید تو همون فایل، `BOT_NAME` و `BOT_USERNAME` رو هم به دلخواه عوض کنید
(فقط جنبه یادداشت داره، تو منطق ربات استفاده نمی‌شه).

## 🔐 مرحله ۵ — تنظیم Secret ها

سه مقدار محرمانه لازمه که **نباید** داخل `wrangler.toml` نوشته بشن؛ با
دستور `wrangler secret put` تنظیم می‌شن و مستقیم رمزنگاری‌شده تو کلادفلر
ذخیره می‌شن:

```bash
npx wrangler secret put BOT_TOKEN
# توکنی که از BotFather گرفتید رو پیست کنید

npx wrangler secret put OWNER_ID
# آیدی عددی تلگرام خودتون (از @userinfobot)

npx wrangler secret put WEBHOOK_SECRET
# یه رشته تصادفی دلخواه، مثلاً خروجی: openssl rand -hex 24
```

`WEBHOOK_SECRET` فقط برای این هست که مطمئن بشیم درخواست‌هایی که به Worker
می‌رسن واقعاً از تلگرام میان، نه از یه منبع دیگه.

```bash

```

## 🔗 مرحله ۷ — وصل کردن Webhook تلگرام

باید به تلگرام بگید که آپدیت‌ها رو به همون آدرس Worker بفرسته. این دستور رو
با مقادیر خودتون جایگزین کنید و تو ترمینال (یا مرورگر) اجرا کنید:

```bash
curl "https://api.telegram.org/bot<BOT_TOKEN>/setWebhook" \
  -d "url=https://vpn-shop-bot.<your-subdomain>.workers.dev" \
  -d "secret_token=<همون WEBHOOK_SECRET که تنظیم کردید>"
```

اگه پاسخ `"ok":true` گرفتید، تمومه — ربات‌تون زنده‌ست. برای چک کردن وضعیت
webhook هر وقت خواستید:

```bash
curl "https://api.telegram.org/bot<BOT_TOKEN>/getWebhookInfo"
```

## 🔁 مرحله ۸ — اتصال به گیت‌هاب برای دیپلوی خودکار

اگه می‌خواید هر بار که کد رو تو گیت‌هاب push می‌کنید، ربات خودکار آپدیت
بشه، دو راه دارید:

### روش A — اتصال مستقیم از داشبورد کلادفلر (ساده‌ترین)

1. تو [داشبورد Cloudflare](https://dash.cloudflare.com) برید به **Workers & Pages**
2. روی Worker خودتون (`vpn-shop-bot`) کلیک کنید → تب **Settings** → بخش **Build**
3. گزینه **Connect to Git** رو بزنید و ریپازیتوری گیت‌هابتون رو انتخاب کنید
4. Branch رو `main` بذارید، Build command رو خالی بذارید (پروژه نیازی به build نداره)
5. از این به بعد هر `git push` روی `main` خودکار دیپلوی می‌شه

> توجه: `wrangler.toml` (با آیدی‌های KV) و Secret هایی که با `wrangler secret put`
> تنظیم کردید همچنان معتبر می‌مونن — این اتصال فقط جایگزین اجرای دستی
> `wrangler deploy` می‌شه.

### روش B — GitHub Actions

فایل `.github/workflows/deploy.yml` بسازید:

```yaml
name: Deploy Worker
on:
  push:
    branches: [main]
jobs:
  deploy:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: cloudflare/wrangler-action@v3
        with:
          apiToken: ${{ secrets.CLOUDFLARE_API_TOKEN }}
```

و تو تنظیمات ریپازیتوری گیت‌هاب → **Settings → Secrets and variables → Actions**،
یه secret به اسم `CLOUDFLARE_API_TOKEN` اضافه کنید (از
[dash.cloudflare.com/profile/api-tokens](https://dash.cloudflare.com/profile/api-tokens)،
با دسترسی *Edit Cloudflare Workers*).

## 👑 اولین اجرا و گرفتن دسترسی Owner

1. تو تلگرام ربات‌تون رو باز کنید و `/start` بزنید
2. بعد یه پیام به ربات از همون آیدی که تو `OWNER_ID` گذاشتید بفرستید: `/admin`
3. چون هنوز هیچ ادمینی ثبت نشده و آیدی‌تون با `OWNER_ID` مطابقت داره، خودکار
   به عنوان **Owner** ثبت می‌شید و پنل مدیریت باز می‌شه

از این به بعد می‌تونید از پنل، ادمین‌های Manager/Support دیگه هم اضافه کنید.

## 🌐 اضافه کردن پنل VPN (Marzban / 3x-ui / PasarGuard)

از `/admin → 🖥 پنل‌ها → افزودن پنل`:

1. نوع پنل رو انتخاب کنید (Marzban / 3x-ui / PasarGuard)
2. آدرس پنل (مثلاً `https://panel.example.com:8000`)
3. یوزرنیم و رمز ادمین پنل
4. بعد از افزودن، از دکمه «تست اتصال» مطمئن بشید لاگین موفقه
5. بعد از `/admin → 👤 پروفایل‌ها` یک پروفایل (پروتکل) روی همون پنل بسازید
6. موقع ساخت محصول، همون پنل و پروفایل رو انتخاب کنید تا خرید از اون پنل سرو بشه

```
    textRegistry.js           # فهرست همهٔ متن‌های قابل‌ویرایش
    state.js                  # مدیریت وضعیت چندمرحله‌ای (منتظر ورودی متنی)
    log.js / report.js        # گروه لاگ (Forum) و کانال گزارش عمومی
    panels/                   # آداپتور هر پنل (marzban.js, threexui.js, pasarguard.js)
  handlers/                   # منطق هر بخش برای کاربر عادی
    admin/                    # منطق کامل پنل مدیریت
wrangler.toml                 # تنظیمات Worker + KV namespace ها + متغیرها
package.json
```

## 🔄 آپدیت گرفتن بعدی

اگه از روش A (اتصال مستقیم گیت‌هاب) استفاده کردید، فقط کافیه push کنید.
در غیر این صورت، بعد از هر تغییر تو کد:

```bash
npx wrangler deploy
```

نیازی به دست زدن به KV یا secret ها نیست — دیتای ذخیره‌شده (کاربران، محصولات،
تنظیمات و...) دست نمی‌خوره.

## 🩺 عیب‌یابی سریع

| مشکل | راه‌حل |
|---|---|
| ربات اصلاً جواب نمی‌ده | `getWebhookInfo` رو چک کنید؛ `url` باید درست و `last_error_message` خالی باشه |
| یه دکمهٔ خاص هیچ کاری نمی‌کنه | با `npx wrangler tail` لاگ زنده رو ببینید — معمولاً یه خطای API تلگرام یا KV اونجا افتاده |
| `/admin` جواب نمی‌ده | مطمئن بشید `OWNER_ID` دقیقاً همون آیدی عددی‌ایه که باهاش پیام دادید (نه یوزرنیم) |
| ساخت اکانت تست/خرید fail می‌شه | از `/admin → 🖥 پنل‌ها` تست اتصال بگیرید؛ مطمئن بشید پروفایل فعال روی اون پنل وجود داره |
| بعد از دیپلوی جدید یه پیام undefined/خالی می‌ره | معمولاً یعنی یه کلید متن/تنظیمات جدید اضافه شده — با یه `wrangler tail` بررسی کنید، این نسخه از `getSettings`/`getTexts` مقادیر قدیمی رو با پیش‌فرض‌های جدید merge می‌کنه پس این مورد نباید پیش بیاد |
